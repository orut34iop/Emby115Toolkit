# 媒体服务配置

“服务配置”入口在七个标签页中始终可用。macOS 位于标签栏右侧；Windows 使用标签栏上方右侧的原生工具条，避免在最小窗口下覆盖标签。

1. 打开“服务配置”，点击“新增服务配置”。
2. 填写名称、可选服务器分组、Jellyfin/Emby 类型、完整服务地址、API Key 和用户名，保存。
3. 选择档案并点击“使用此配置”，或在三个媒体页面的“当前媒体服务”下拉框中切换。

配置单位是一套媒体服务实例。同一机器的 Jellyfin、Emby、不同端口或反向代理路径都可分别保存。名称和分组只是显示信息，内部使用独立 ID。未保存的修改会在关闭或更换编辑对象前提示；密钥默认隐藏。

“合并版本、更新流派、更新地区”共用当前选择。其他四个标签页继续使用各自的本地路径；打开/关闭配置管理或切换实例不会更改其路径，也不会切换原标签页。重新启动恢复上次选择。

媒体任务开始时固定连接参数。任一媒体任务尚未结束时，切换和配置管理保持锁定；点击停止后需等待工作线程实际结束。不同媒体功能按顺序执行，并分别保存增量进度，避免并发提交整条媒体元数据时互相覆盖。修改地址、服务类型、用户名或密钥会清除该档案的旧增量基线，下次自动重新建立；改名或分组不清除进度。

## 旧配置与保存

首次加载旧配置时，在配置目录创建 `config.yaml.pre-media-profiles-*.bak`，保留迁移前的原始文件。原功能页面中不同的连接参数分别导入为“原配置 · 功能名”，完整连接参数相同的档案合并。缺项的旧配置仍保留，可在管理窗口补齐。不会根据相同 IP 合并服务。

数据保存在 `config.yaml` 的 `media_servers` 中，包含 schema 版本、实例列表和当前 ID；每实例的 `settings` 按功能分别保存扫描模式及增量状态。旧功能字段为迁移兼容保留，迁移后媒体页面只读取实例档案，不再使用旧字段。备份与配置均可能包含密钥，应沿用本机配置文件的管理方式。

写入采用加锁、临时文件及原子替换。配置格式、备份或迁移失败时保留原文件；档案写入失败不会切换内存中的活动配置或提示成功。

## 已确认设计与实现边界

- 决策 UI-MS-01，批次 MS-01；用户确认：“OK 就按照这个方式实现”。
- 七页名称、顺序、本地业务操作保持原范围；新增共享实例管理与选择。
- macOS 采用原生 Qt 下拉框和 QDialog，Windows 采用 ttk 控件和模态 Toplevel。
- 管理窗口采用“左侧实例列表、右侧连接表单”。参考：[DataGrip 官方数据源管理](https://www.jetbrains.com/help/datagrip/data-sources-and-drivers-dialog.html)。
- 友好名称与 ID 分离参考 [Jellyfin Web 服务选择](https://github.com/jellyfin/jellyfin-web/blob/5783c293246f1a404649e6f43a45c3c1e830e4dd/src/apps/legacy/controllers/session/selectServer/index.js)；仅参考模式，未复制 GPL 代码或素材。
- 未加入批量跨服务器执行、真实连接探测、后台自动同步或新的工具标签。

验证覆盖迁移备份、独立实例、重启恢复、并发状态、失败回滚、锁生命周期、七页共享入口、未保存表单以及本地路径保持。Windows 原生 GUI 测试只在 Windows 上执行，并通过独立 GitHub Actions 工作流运行；macOS 使用 Qt 工作流与原生窗口检查。
